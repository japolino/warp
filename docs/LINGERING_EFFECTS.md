# Lingering effects in ordinary play

Implementation contract, 2026-11-04. This extends the shared default engine; it introduces no genre preset, rulebook or setup screen.

- A periodic ability applies one named condition with a saved pulse and either a finite number of subsequent affected-owner actions or an actual source-defined ending. Qualitative ongoing effects can use labelled Warp action timing when no source interval exists; explicit seconds/round rules are never converted. Damage, recovery and qualitative physical harm/treatment reuse existing defenses, limits and injury rules. No recursive pulse, additional model call, wall-clock timer or offscreen turn loop.
- A currently narrated active affliction can adopt its future schedule directly from the latest actual narrator source, without inventing its original caster, a player-owned power, past costs or prior damage. An explicit remaining count is required for finite schedules. Repeated old prose cannot refresh a schedule or resurrect a cured effect.
- Actual ongoing fire, bleeding, toxin harm or recovery can use fixed Warp ending cues when the source supplies no ending. The cue is labelled an engine rule. Never apply these mappings to metaphors, unknown illness, curses or an explicit source prohibition. A later completed environmental ending can stop an ongoing schedule without healing prior damage; counted cures still require their own receipts.
- Ongoing routine physical recovery can gradually reduce a supported narrative injury grade; a minor-only treatment still cannot treat a major injury. Special injuries remain special. The recovery cue ends only when its supported treatment is complete, never after an invented count or at an unknown resource limit.
- Resolve the actual action first, then its previously scheduled pulses. An effective cure before that boundary cancels its pulse. Refreshing a due effect cannot cancel its already scheduled pulse; the refreshed schedule remains separate. Newly applied effects do not tick on their application action.
- Supported actions, including explicit waiting, can advance a schedule. Questions, inspection, API waiting, denied/cancelled actions and withdrawing a plain resource permission do not. NPCs follow the same rules. Incapacity/death does not create an automatic action.
- Buildup accumulates an explicit source amount toward its explicit threshold. Qualitative source accumulation may instead use Warp's fixed minor/standard/major steps of 1/2/3 toward 3, labelled Warp values. Do not turn instant effects, ordinary affection or social disagreement into invented accumulation.
- Crossing a threshold consumes the threshold and retains the remainder. The trigger applies or refreshes one condition or periodic effect with an ending. Multiple crossings in the same application coalesce because the trigger is idempotent, never extra attacks or resource rewards. Nested buildup and arbitrary scripts are unsupported.
- The same owner/name shares buildup only when its threshold and trigger definitions agree. Conflicting definitions stay unresolved. Source-backed clearing resets the named accumulation. New effects do not reset paid costs or stale injuries.
- Validate required resources and treatment limits before payment. Unknown health is not zero health and is not a new HP pool. Unsupported timing and triggers remain explicit.
- Resolver 9 owns these operations. Resolver 2 through 8 receipts retain their former execution paths, rolls and results. Stop, retry, swipe, reload and edited-source handling use the existing receipt boundaries.
- Keep historical prompt bytes. Conditions already participate in deltas; add the buildup collection and lingering boundary to the retained-wire projection. Relevant counts, remaining pulses and consequences can be inspected or requested in chat. Show only immediate consequential changes in the normal strip.

Verification must cover fixed-order shields/resistance/reflection, finite refresh/cure behavior, repeated thresholds and conservation, both actors, missing resources, rejected/failed/cancelled actions, branch replay, old resolver goldens, actual worker execution, prompt delivery/prefix preservation and appropriate real cards. Tests do not establish calibrated balance or enjoyment.

Verified before installation: 826 tests and 20,872 assertions, typecheck and production build. The actual Lumiverse worker passes the seven-turn periodic/buildup scenario and prior growth/companion-withdrawal scenarios; the production frontend passes its scoped DOM checks. Public scenes read by the selected real helper cover active fire, active regeneration, a romance metaphor and extinguished sci-fi flames. Initial provider timeouts and a missing ending discriminator were retained as failed evidence; clarified schema and captured-response replay cover the repaired path. No provider cache-hit claim is made.

The first isolated Slime-card attempt exposed a post-read loophole: an unresolved activation was described as focusing toward an invocation, then the scene reader offered a new ongoing recovery. The tracker now rejects new periodic observations from a reply whose validated preparation was blocked, including during replay. The scene reader receives the actual preparation result. This prevents a prose read from bypassing a rejected action; it does not make a newly claimed power established.
